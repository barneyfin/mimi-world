# MeeMee World

Barney's maths and phonics games for a five-year-old, played on two tablets: one web page with a home map where each game is a planet.

- `MEEMEE.md` holds the rules for every game. Read it before any work here. The kit's docs add to it; if they disagree, stop and ask Barney which wins.
- For any game work, use the `meemee-world` skill (`.claude/skills/meemee-world/`) and read its `reference.md` and `design.md` before writing code.
- Layout: `kit/` is shared by every game; `games/<id>/` is one game (`games/rescue/` is the worked example, `games/_template/` the starting point); `design/` holds the drawings and colour tokens; `voice/` holds Barney's recordings; `docs/` is the built website (generated by `python tools/build.py`, never edited by hand); `tools/tests/` holds the checks.
- Do not change `kit/` or `design/` while working on a game. Changing them is its own job, only when Barney asks; afterwards rebuild, run both test suites, and say which games you checked.
- The repository and the website are public: never write the child's name anywhere in them, including commit messages. The names to avoid are in `tools/private-names.txt` (on the PC only, never committed).
- Barney is on Windows and is learning to build software: explain what you did and why in a few plain sentences, say clearly what you could not test, and say which shell any command is for.
- Git is Barney's: do not commit, push or create branches unless he asks. Give him the commands for PowerShell, one at a time, with the full path; long commit messages go in a `CMn.txt` in the repo root that he moves into `.git` and uses with `git commit -F`.
- Python on Barney's PC: `C:\Users\barne\AppData\Local\Programs\Python\Python312\python.exe`.
